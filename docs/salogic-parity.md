# SALOGIC → Salon OS 機能照合表

現在使っている美容サロン管理アプリ **SALOGIC**（`admin.salogic.app`）を Salon OS で置き換えるための照合表です。
SALOGIC の画面にある機能を1つずつ挙げ、Salon OS が対応しているかを記録します。

- 調査日: 2026-10-13
- 調査方法: SALOGIC にオーナー権限でログインし、全メニュー・全タブ・設定項目を**閲覧のみ**で確認（保存・削除・送信・予約変更・取込のボタンは押していない）。対象店舗は1店舗（他店舗は同じ構成の想定）。
- Salon OS 側はコード（マイグレーション・API・画面）を読んで判定。README の記述ではなく実装で判断している。
- お客様の個人情報、スタッフの個人名、媒体のログイン情報はこの文書に含めない。

## 0. 先に知っておくべき大きな違い

1. **サロンボード連携の方式が違う**（方針差）。SALOGIC はサロンボードの ID・パスワードを預かって自動で読み書きする。Salon OS は [ADR 0010](adr/0010-mail-based-booking-media-sync.md) により、サロンボード → Salon OS は**予約通知メールの転送**で自動取り込み、Salon OS → サロンボードは**スタッフへの枠止め依頼**（手作業 +「対応済み」）とする。サロンボードのログイン画面には自動操作の検知が組み込まれており、SALOGIC 自身も設定画面に「利用規約に抵触する可能性」と注意書きを出している。
2. **SALOGIC に CSV 書き出しの画面は無い**。全メニューを確認したが、CSV・エクスポート・ダウンロードのボタンは無かった。データ移行（[migration.md](migration.md)）の入力は、サロンボードの書き出し、または SALOGIC 運営への書き出し依頼で用意する必要がある。
3. **Salon OS の方が多い機能**: 予約の編集・キャンセル・来店・会計、POS、顧客 CSV 書き出し、統合の取り消し、同意書の電子署名など。SALOGIC の予約詳細には編集・キャンセル・会計のボタンが無かった。

## 3. 顧客管理（カルテ）

2026-10-14 に SALOGIC と同じ画面構成へ作り替えた: 顧客一覧（`/app/customers`、`web/routes/app/customers/Customers.tsx`。見出しは SALOGIC と同じ「カルテ」）→ 顧客詳細（`/app/customers/<id>`、`CustomerShow.tsx`）→ カルテ詳細（`/app/customers/kartes/<id>`、`KarteShow.tsx`）、新規顧客登録（`/app/customers/new`、`CustomerCreate.tsx`）。以前の顧客詳細（タグ・スタッフメモ・ポイント・書類・タイムライン・統合の取り消し・LINE 連携 QR）は `/app/customers-classic/<id>` に残し、新しい顧客詳細の左カード最下部のリンクから開く。以前のカルテ編集（テンプレート項目・薬剤・ホームケア・共有リンクの期限/通知）は `/app/kartes/<id>` に残し、カルテ詳細の「施術内容」カード内のリンクから開く。

SALOGIC との違い:
- 顧客は法人単位（SALOGIC は店舗ごとに別レコード）。「同一人物としてリンク」は SALOGIC と同じく会員番号を共有するだけでレコードは統合しない（`customers.member_no`）。全員が同じ会員番号になったグループは名前重複の一覧から外れる。
- 統合候補は LINE ↔ 既存に限らず、電話一致・メール一致・誕生日+氏名類似の組をすべて出す。LINE から来たレコードは「LINE」、それ以外は「重複」と表示し、LINE 側を既存側へ統合する（どちらも LINE でない / 両方 LINE のときは来店回数の多い方を残す）。確認文の「この操作は取り消せません」は SALOGIC と同じ文言だが、Salon OS では以前の顧客詳細から統合を取り消せる。
- 顧客詳細「メッセージ」タブは SALOGIC では「準備中」の表示だが、Salon OS では実際のメッセージ画面（やり取り・配信設定・LINE 連携 QR）を出す。
- 予約履歴には、移行した旧システムの来店履歴も同じ形の行で並ぶ（時刻なし・完了・施術メモつき）。
- カルテタブの「追加」（今日の日付・ログイン中のスタッフでカルテを作って編集を開く）は SALOGIC に無い。SALOGIC のスタッフ画面にはカルテを新規作成するボタンが見当たらなかったため足した。
- カルテの「共有」は共有リンクを発行してクリップボードにコピーする（お客様への通知は以前のカルテ編集画面から）。共有ページには 施術内容の固定7項目・写真・フェイス描画が出る（内部メモは出ない）。
- 住所検索は SALOGIC と同じく郵便番号 7 桁で zipcloud（外部の無料 API）を呼ぶ。

## 4. 同意書

## 11. サロンボード（ホットペッパービューティー）連携

要件:「ダブルブッキングが無いように、どちらも最新状態で連携する」。

| 方向 | SALOGIC | Salon OS | 状況 |
|---|---|---|---|
| サロンボード → 自システム | 予約メール受信 + ログインして取得 | 予約通知メールの転送で自動取り込み（新規・変更・キャンセル）。数秒〜数十秒で反映 | 済（方式は同等） |
| 自システム → サロンボード | ログインして自動書き込み | スタッフへ「枠を止める / 再開する」依頼を通知。スタッフがサロンボードで操作し「対応済み」を押す | 方針差 |
| 予約ごとの連携状態 | 予約詳細に「SB連携済 / SBエラー」と再試行 | 予約詳細に SALOGIC と同じ SB チップ・SB連携行・再同期ボタン（8章）、カレンダーにバッジ ✅ | 済 |
| 既存予約の一括取り込み | — | 媒体 CSV の一括取り込み（確認つき） | 済 |
| スタッフ名・メニュー名の対応付け | 対応スタッフ表に SB 名 | スタッフ編集の サロンボード スタッフ名/ID → 対応表 → 名前の自動一致 → 既定メニュー。対応スタッフ表の列見出しに SB 名を小さく表示 ✅ | 済 |

ダブルブッキング防止のために運用で必ず行うこと:

1. 連携設定で **`pushBlocks`（枠止め依頼）を有効にする**。既定は無効で、無効のままだと Salon OS 側の予約がサロンボードに伝わらない。
2. 枠止め依頼の通知先メール（`notifyEmails`）を受付担当全員にする。
3. 予約通知メールの読み取りラベルを、**実際の通知メールで確認する**（`parse-test`）。コード上の初期値は実メールで未検証と明記されている。
4. 重なり時の方針（`manual` / `external_wins` / `internal_wins`）を決める。

残るリスク: スタッフがサロンボードで枠を止めるまでの間は、両方に同時に予約が入る余地がある。完全にゼロにはできない。
