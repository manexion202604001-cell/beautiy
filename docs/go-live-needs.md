# 会社で使い始めるために必要なもの

Salon OS を fein の 6 店舗で SALOGIC の代わりに使い始めるまでに、**オーナー側で用意・判断が必要なもの**の一覧です。
ソフト側の作業（画面・機能）は別に進めています。画面ごとの対応状況は [salogic-parity.md](salogic-parity.md)、
デプロイ手順は [deploy.md](deploy.md)、切り替え手順は [migration.md](migration.md) を見てください。

- 更新日: 2026-10-14
- 記号: 🔴 これが無いと始められない / 🟡 切り替え日までに必要 / 🟢 後からでよい

## 1. 置き場所（サーバー）

| | 必要なもの | 内容 | 誰が |
|---|---|---|---|
| 🔴 | Render のアカウントと有料プランの契約 | DB・API・ワーカー・Web の 4 つを動かす。`render.yaml` を読み込ませるだけで作成される。料金は Render の料金ページで確認 | オーナー（アカウント作成・支払い情報の入力は本人のみ可能） |
| 🔴 | GitHub リポジトリへの Render のアクセス許可 | Render の画面で `manexion202604001-cell/beautiy` を選ぶ | オーナー |
| 🟡 | 独自ドメイン（任意） | 例: `app.fein-salon.jp`。無ければ `xxx.onrender.com` のまま使える。受信メールの転送先 URL もこのドメインになる | オーナー |
| 🔴 | DB の接続ユーザーの確認 | API とワーカーは、テナント分離を守るため、スーパーユーザー / BYPASSRLS のロールでは起動しない。Render の既定ユーザーがこれに当たる場合は一般ロールを 1 つ作る（[operations.md](operations.md) 2.3 節に確認 SQL） | 初回デプロイ時に確認 |
| 🟡 | バックアップの設定 | Render の DB バックアップ（保持日数）を有効にする | オーナー |
| 🟡 | アクセス回数の上限の調整 | API は 1 つの回線（IP アドレス）あたり 1 分 300 回までに制限している。1 店舗で多くの端末（目安 10 台以上）が同じ Wi-Fi から同時に使うと「リクエストが多すぎます」と出ることがある。その場合は環境変数 `RATE_LIMIT_MAX` を上げる（例: 1200） | 初回デプロイ時に設定 |

## 2. 外部サービス（接続情報）

| | 必要なもの | 何に使うか | 設定先 |
|---|---|---|---|
| 🔴 | LINE 公式アカウント（店舗ごと or 法人で 1 つ）の Messaging API チャネル: チャネル ID・チャネルシークレット・アクセストークン | メッセージの送受信、予約通知、お客様の LINE 連携 | 管理画面で登録 + 環境変数 `LINE_DRIVER=live` |
| 🔴 | LINE ログインチャネル（Messaging API チャネルと同じプロバイダー）+ LIFF アプリ（エンドポイント URL = 公開ドメインのルート `https://<WEB_BASE_URL>/`、scope `openid` `profile`）: LINE ログインのチャネル ID・LIFF ID。友だち追加 URL（https://lin.ee/…） | LINE の中で受付・LINE 連携・予約・マイページを開き、お客様の LINE を自動で連携する。友だち追加ボタン | 管理画面（連携 › LINE公式アカウント）で登録 |
| 🟡 | メール送信（SMTP）の接続情報と差出人アドレス | 予約確認、パスワード再設定メール、枠止め依頼 | 環境変数 `EMAIL_DRIVER=smtp` `SMTP_URL` `MAIL_FROM` |
| 🟡 | 写真の保存先（S3 互換。Cloudflare R2 など）のバケットとキー | カルテ写真・メニュー写真・スタッフ写真・CSV 出力。**未設定だとデプロイのたびに写真が消える** | 環境変数 `STORAGE_DRIVER=s3` ほか |
| 🟢 | SMS 送信サービス | SMS での確認コード・通知（使う場合のみ） | 環境変数 `SMS_DRIVER=live` |
| 🟢 | Stripe のキー | オンライン決済（使う場合のみ） | 環境変数 `PAYMENT_PROVIDER=stripe` |
| 🟢 | Anthropic API キー | AI の下書き（未設定でも動く） | 環境変数 `ANTHROPIC_API_KEY` |

## 3. サロンボード（ホットペッパー）連携 — 今夜の作業の対象外

今の Salon OS は「予約通知メールの転送で自動取り込み」＋「Salon OS で入った予約は、スタッフがサロンボードで枠を止める」方式です（[ADR 0010](adr/0010-mail-based-booking-media-sync.md)）。SALOGIC のような ID・パスワードを預かる自動操作は入れていません。

| | 必要なもの | 内容 |
|---|---|---|
| 🔴 | 方式の決定 | (a) 今の方式で始める / (b) 自動で書き込む方式を別途検討する（サロンボードの利用規約に抵触する可能性あり）。以前の希望は「どちらも最新状態で、ダブルブッキングが無いように」 |
| 🟡 | メール受信サービス（SendGrid Inbound Parse / Mailgun / Postmark のいずれか）と受信用サブドメイン | サロンボードの予約通知メールを Salon OS に届ける（(a) の場合） |
| 🟡 | サロンボードの通知メールの転送設定 | 店舗ごとに、通知先へ受信用アドレスを追加 |

## 4. 移行するデータ

| | 必要なもの | 内容 |
|---|---|---|
| 🔴 | 顧客・来店履歴・今後の予約のデータの入手元の決定 | SALOGIC には CSV 書き出しの画面が無い。(a) サロンボードの CSV 書き出しを使う / (b) SALOGIC の運営に書き出しを依頼する |
| 🟡 | 6 店舗分の CSV（顧客 / 来店履歴 / 今後の予約） | 取り込みは「サロン管理 › データ移行」。数十行の試しファイルで確認してから全件 |
| 🟡 | SALOGIC のメッセージ履歴・同意書・カルテ写真をどうするか | CSV 取り込みの対象外。SALOGIC を閲覧用に 1 か月残す前提（[migration.md](migration.md)） |

## 5. 店舗ごとの初期登録（画面から入力するもの）

SALOGIC の設定画面と同じ内容を Salon OS に登録します。調査できたのは青山店のみなので、**他の 5 店舗（心斎橋・明治神宮前・渋谷・福岡・表参道）は各店で確認が必要**です。

| | 必要なもの |
|---|---|
| 🔴 | 6 店舗の基本情報（店名・住所・電話・営業時間・定休日） |
| 🔴 | スタッフ全員の表示名（**SALOGIC と同じ表記**）・権限（オーナー / ディレクター / スタッフ）・ログイン用メールアドレス・所属店舗・勤務時間 |
| 🔴 | メニュー一覧（**予約で使っている名前と同じ**）・所要時間・料金・分類と分類の色・対応スタッフ・掲載/非掲載 |
| 🟡 | メニューとスタッフの写真 |
| 🟡 | 同意書の本文（約 2,700 字、店舗固有）とカウンセリングシートの質問（[salogic-parity.md](salogic-parity.md) 付録 A・B に構成あり） |
| 🟡 | 予約受付のルール（何分前まで受け付けるか、キャンセル期限、リマインドの時刻と文面） |
| 🟡 | 自動メッセージの文面（予約確定・リマインド・来店後など） |

## 6. 判断が必要なこと

| | 判断すること | 補足 |
|---|---|---|
| 🔴 | 切り替え日と順番 | 1 店舗（青山店）で試してから全店、を推奨。切り替えは [migration.md](migration.md) の手順で約 2 週間 |
| 🟡 | SALOGIC のログインパスワードの変更 | 2026-10-13 の作業中に、推測されやすいパスワードが画面に表示されているのを確認した |
| 🟡 | スタッフへの操作説明の時間 | 画面は SALOGIC と同じ構成にしてあるが、会計・カルテなど Salon OS にしかない機能は「設定 › その他の機能」から開く |
| 🟢 | 配色 | 現在はピンク×ホワイト（2026-10-13 指定）。色は 1 か所の設定で変えられる |

## 7. 画面ごとに必要なもの

各画面を SALOGIC と同じにする作業（2026-10-13〜14）の中で分かった、画面固有の準備物と確認事項です。
SALOGIC との機能差の一覧は [salogic-parity.md](salogic-parity.md) にあります。

### 7.1 予約管理・ダッシュボード

| | 必要なもの / 確認すること |
|---|---|
| 🟡 | 予約詳細の「同意書 QR」は、同意書フォーム（種類: 同意書）が 1 つ以上登録されていると表示される（7.5 参照） |
| 🟡 | お客様へのメッセージ送信で「公式LINE」を使うには LINE 公式アカウントの接続が必要（2 章） |
| 🟢 | 予約経路（HPB / minimo / 電話 など）の選択肢は SALOGIC と同じ。追加したい経路があれば連絡 |

### 7.2 顧客管理（カルテ）

| | 必要なもの / 確認すること |
|---|---|
| 🔴 | **SALOGIC のカウンセリングシート・カルテ・施術写真は書き出し画面が無い。** 引き継ぐには SALOGIC の運営にデータの提供を依頼する（カウンセリングは SALOGIC と同じ 7 分野・85 問の構成にしてあるので、JSON でもらえればそのまま取り込める） |
| 🟡 | 「統合候補」「名前重複」を処理できるのはオーナーと店長（ディレクター）のみ。6 店舗分を取り込むと名前重複が多数出るので、誰が整理するか決める |
| 🟡 | カルテの「共有」でお客様に見せる範囲の確認: 施術内容の 7 項目・写真・フェイス描画を見せ、内部メモは見せない（SALOGIC の「内部メモのみ非公開」に合わせた） |
| 🟡 | 住所の自動入力は外部の無料サービス（zipcloud）をブラウザから呼ぶ。SALOGIC と同じ方式。使ってよいか確認 |
| 🟡 | 写真の保存先を S3 互換にした場合、アプリの URL からの読み出し（CORS の GET）を許可する。許可が無いとフェイス描画の続きが描けない |
| 🟢 | 「スタッフ集客 / 個人」の区分はデータ移行でのみ入る（SALOGIC にも設定画面は無い）。画面から付けたい場合は連絡 |
| 🟢 | カウンセリングシートは顧客 1 人につき 1 枚（SALOGIC は店舗ごとの顧客に 1 枚） |

### 7.3 メニュー

| | 必要なもの / 確認すること |
|---|---|
| 🔴 | メニュー・クーポン・カテゴリ（親子と色）を 6 店舗分登録する。SALOGIC の「SBから取込」ボタンはサロンボード連携のため未搭載なので、手入力か CSV で入れる |
| 🔴 | メニューごとの対応スタッフ。**Salon OS では 1 人もチェックしていないメニューは全員が対応可能**（SALOGIC は誰も対応不可）。SALOGIC のチェック状態をそのまま写す |
| 🟡 | 設備（アイラッシュ・エステ・ネイル・リラク などの台数）を「店舗設定 › 設備」に登録し、メニューに紐付ける |
| 🟡 | メニュー写真（保存先の設定が必要。2 章） |
| 🟢 | カテゴリの「全削除」は組織共通のカテゴリも消える。実行できるのはオーナーのみ |

### 7.4 スタッフ・予約受付設定

| | 必要なもの / 確認すること |
|---|---|
| 🔴 | スタッフ全員のメールアドレス。SALOGIC の「6 桁のスタッフ ID で招待」は Salon OS では「メールアドレスで招待」。メール送信が未設定の間は、招待リンクを画面からコピーして渡す |
| 🔴 | 予約受付設定に今の SALOGIC の値を入れる: 曜日ごとの営業時間、祝日（10:00〜19:00）、受付可能数（全曜日 11 人。**「祝」の行にも 11 を入れる**）、2 ヶ月先まで、当日 1 時間前まで |
| 🔴 | スタッフごとの歯車（営業時間・予約設定）: 例 30 日先まで / 3 時間前まで / 同時 1 人。未設定のスタッフは「同時に 1 件」「サロンの受付期間」で動く |
| 🟡 | 権限の対応の確認: SALOGIC のオーナー / ディレクター / スタッフ = Salon OS のオーナー / 店長 / スタイリスト。細かい権限は「設定 › その他の機能 › 権限ロール」で変えられる。権限は店舗ごとではなく会社全体で 1 つ |
| 🟡 | スタッフへの LINE 通知: 店舗の LINE 公式アカウントを接続し、各スタッフがそのアカウントに「ID確認」と送ると返ってくる User ID をスタッフ編集に入れる |
| 🟡 | スタッフの写真とニックネーム（お客様の予約画面に出る名前） |
| 🟡 | 判断: 「ログイン情報を設定」で発行した仮パスワードを、初回ログイン時に必ず変更させるか（今は任意） |
| 🟢 | スタッフの並び順は会社全体で 1 つ（SALOGIC は店舗ごと）。メール認証の手順は無いので「メール認証を承認」ボタンは無い |

### 7.5 同意書一覧・メッセージ

| | 必要なもの / 確認すること |
|---|---|
| 🔴 | 同意書の本文を「設定 › その他の機能 › 問診・同意書フォームの編集」に登録する（種類: 同意書。本文の `## 見出し` ごとに折りたたみ表示）。デモ用の「カラー施術同意書」は不要なら削除（アーカイブ）する |
| 🟡 | 受付 QR を印刷して店頭に置く（同意書一覧の右上「受付QRコード」。スタッフ別の QR も出せる）。QR の URL は公開ドメインが決まってから印刷する |
| 🟡 | LINE（LIFF）経由の受付: LINE アカウントに LIFF ID を登録すると受付 QR が LINE で開く QR に変わる。**LIFF ID を登録してから QR を印刷する**（未登録のまま印刷した QR は LINE 連携なしの受付になる） |
| 🟡 | メッセージの「公式LINE」のチェックを外したとき: SALOGIC は「メモとして記録するだけ」。Salon OS も同じ動きにしてある。メール / SMS へ自動で切り替えて送りたい場合は連絡 |
| 🟢 | 破棄した受付（同意書）の保存期間を決める（今は残り続ける） |

### 7.6 店舗設定・設定

| | 必要なもの / 確認すること |
|---|---|
| 🔴 | 6 店舗を「設定 › 店舗一覧」で作成し、「店舗設定」に住所・電話・席数アラート（同時最大予約数）を入れる |
| 🟡 | 「設定 › オーナー情報」（事業形態・会社名・住所・連絡先） |
| 🟡 | 「設定 › スタッフ管理」で、スタッフごとの所属店舗とお客様への表示 / 非表示を SALOGIC と同じにする |
| 🟢 | 店舗の削除は「非表示にする」動きで、データは残る（誤操作で予約や顧客が消えないようにするため） |
| 🟢 | 「店舗設定 › サロンボード」タブはサロンボード連携のため未搭載（3 章） |

### 7.7 Salon OS にしかない機能の場所

会計（POS）・売上分析・シフト・キャンペーン配信・口コミ・EC・データ移行・外部連携などは、
SALOGIC と同じメニュー構成を保つため「設定 › その他の機能」にまとめてあります。以前の画面（顧客詳細・スタッフ詳細・メニュー・メッセージ・店舗設定の旧版）もそこから開けます。
