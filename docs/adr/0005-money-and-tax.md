# ADR 0005: 金額は整数円・内税、消費税は税率ごとに1回端数処理（インボイス制度）

- 状態: 承認（Accepted）
- 日付: 2026-10-01
- 関連: requirements.md FR-04 / AC-21〜25、`lib/money.ts`、`0007_commerce_pos_payments.sql`

## Context（背景）

- 美容サロンの価格表示は総額表示（税込）が一般的で、メニュー・商品価格は税込で登録される。
- 店販で軽減税率（8%）の商品（飲料・食品）を扱う場合があり、10% と 8% が1会計に混在し得る。
- 適格請求書（インボイス制度）では「税率ごとに区分した対価の額と消費税額」を記載し、端数処理は **1つの請求書につき税率ごとに1回** とされる。登録番号（T + 13桁）の記載が必要。
- 値引・クーポン・ポイント利用を明細に按分し、担当スタッフ別売上の合計を会計合計に一致させたい。
- 浮動小数点演算による1円ずれ（例: 1100 × 10/110 = 99.999…）を避けたい。

## Decision（決定）

1. **金額はすべて整数円**（`int`、集計は `bigint`）。小数を保存しない。税率は basis points（`tax_rate_bp`、1000 = 10%、800 = 8%）。
2. 価格は **税込（内税）** を既定とする（`price_tax_included = true`）。税抜登録のメニュー/商品は `toInclusive()` で税込に換算してから明細化する。
3. 会計の税計算は、値引按分後の **税率ごとの税込合計に対して1回だけ** 内税額を算出する: `tax = roundYen(合計 × rate / (10000 + rate))`。端数処理は店舗設定 `pos.roundingMode`（既定 `floor` = 切り捨て）。結果を `transactions.tax_breakdown = { "<rate_bp>": { taxable, tax } }` と `tax_total` に保存する。
4. 行別の税額（`transaction_items.tax_amount`）は、税率ごとの税額を行金額で `allocate()`（最大剰余法）により按分し、合計が税率別税額と一致するようにする。行ごとに端数処理して合計することはしない。
5. 値引・クーポン（会計全体）・ポイント利用は、対象行の金額比で `allocate()` により按分する。スタッフ配賦（`transaction_item_staff.share_bp`、合計10000）も行金額を `allocate()` で按分し、`allocated_amount` の合計は行金額に一致する。
6. 確定後の会計は変更しない。取消（`voided`）・返金（`refunds` + `refunded`/`partially_refunded`）は状態と別レコードで表し、ポイントは `revert`、在庫は `stock_movements` で戻す。
7. 会計番号・レシート番号・注文番号は `counters`（`(organization_id, scope)` 単位、例 `tx:<shop_id>:<年>`）を会計確定トランザクション内で `UPDATE … RETURNING` して採番し、欠番・重複を防ぐ。
8. 領収書には `organizations.invoice_registration_number`、税率別の対価・税額、発行日、宛名、但し書きを記載し、描画内容を `receipts.content` にスナップショット保存する。

## Consequences（結果）

**良い点**
- インボイス制度の端数処理ルールに準拠し、レシート上の税率別税額と合計が必ず一致する。
- 按分・配賦の合計が常に一致し、スタッフ別売上・メニュー別売上の合計が会計合計と整合する（分析の信頼性）。
- 整数演算と `roundYen()` の誤差ガードで1円ずれを防ぐ。

**悪い点・リスク**
- 行ごとの税額は按分値であり、「行単位で計算した税額」とは一致しない場合がある（帳票上は税率別合計が正）。
- 税抜価格の店舗では、明細単位の税込換算で端数が出る（換算ルールを店舗に明示）。
- 多通貨・海外税制には対応しない（MVP 対象外、19.1）。
- `counters` 行が店舗×年ごとの更新ホットスポットになる（1店舗の会計頻度では問題にならない想定）。

## Alternatives（検討した代替案）

| 案 | 不採用理由 |
|---|---|
| 行ごとに税額を計算して合計 | インボイス制度の「税率ごとに1回の端数処理」に反し、レシート合計とずれる |
| decimal 型・浮動小数点で保存 | 円未満の値が残り、按分・集計の一致を保証しにくい |
| 税抜を既定 | 総額表示が一般的なサロン業務と合わない |
| シーケンス（`CREATE SEQUENCE`）で採番 | ロールバックで欠番が生じる。店舗×年の採番範囲を作りにくい |
